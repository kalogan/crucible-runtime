# v0.1 Specification — The Benchmark Kernel

*The smallest end-to-end runtime that proves the architecture viable. This
document is the implementation contract for v0.1: build exactly this, nothing
more.*

> **The risk v0.1 answers:** *Can a local open-weights model reliably execute a
> multi-step native tool-calling loop to produce a verifiable engineering
> outcome?* Everything else in [ARCHITECTURE.md](ARCHITECTURE.md) is downstream
> engineering and is deliberately **out of scope** here.

---

## 1. The benchmark (v0.1 exit criteria)

**`fix-failing-test`** — a single agent session, given an Architect prompt and
a tiny fixture repository containing one intentionally broken implementation
and one failing unit test, must:

1. Run the test suite and observe the real exit code (non-zero).
2. Inspect the repository using native tool calls only.
3. Locate the bug in the source file.
4. Edit the source file (never the tests).
5. Re-run the test suite.
6. Finish with the suite at exit code 0.

Under: **zero human intervention · no orchestration · no text-parsed commands ·
native tool calling only · every action journaled to a JSONL transcript.**

### Director decisions (locked 2026-07-03)

| Fork | Decision |
|---|---|
| Reference model | **`qwen3:14b`** via Ollama is the **required pass**. Comparison models (`qwen3:8b`, future coding models) are optional, recorded, non-blocking. |
| Scoring | **≥ 4 of 5 runs pass.** The 5-run pass rate is the standing regression metric for every future runtime/prompt change. |
| Fixture stack | **TypeScript + vitest** (house style) — the benchmark resembles real Builder work. |

### Derived decisions (Architect-settled; consistent with the constraints)

- **Sampling:** fixed temperature per the model's recommended tool-use config;
  **seeds 1–5**, one per run, recorded in each transcript. (Temp-0 identical
  runs would make 5 runs meaningless; varied seeds measure reliability.)
- **Thinking mode:** enabled for qwen3 (its hybrid-reasoning mode measurably
  helps multi-step tool chains). Recorded in the run config; comparison runs
  may toggle it.
- **Edit mechanism:** `write_file` full-file overwrite only. Small local models
  are far more reliable rewriting a small file whole than emitting diff/patch
  formats. `edit_file` (string-replace) arrives in v0.2.
- **Write surface:** the fixture declares `writableSurface: ["src/**"]` — the
  runtime hard-denies writes to tests and config. This is the minimal seed of
  the architecture's surface enforcement, and it makes "the agent fixed the
  source, not the test" *mechanical* rather than audited.
- **Iteration guard:** max **24** loop iterations per run; **10 min** wall-clock
  per run; both budget-exceeded outcomes count as run failures.
- **Fixture hermeticity:** `pnpm-lock.yaml` committed and frozen; the harness
  installs deps **once** into a cached fixture template
  (`pnpm install --frozen-lockfile`), then copies the template into a fresh
  scratch workspace per run. Network is touched at most once per machine, never
  per run. Node/pnpm/vitest versions are recorded in the report.

## 2. Exact acceptance criteria

v0.1 exits when **all** of the following hold:

**A. Benchmark result**
- [ ] On `qwen3:14b` (pinned tag + digest recorded), 5 runs with seeds 1–5:
      **≥ 4 succeed**.

**B. Per-run success definition** — a run succeeds iff:
- [ ] The **harness itself** re-runs `pnpm test` in the run's workspace after
      the session ends and observes **exit 0**. The agent's claim is never the
      signal (the pipeline's core rule, applied to our own benchmark).
- [ ] Test files, vitest config, and `package.json` are **byte-identical** to
      the fixture (hash-compared before/after) — enforced live by the write
      surface, verified again post-hoc.
- [ ] The transcript shows an initial test execution with a **non-zero exit
      code** *before* any `write_file` call (the agent observed the failure; it
      didn't fix blind).
- [ ] Zero human intervention: no session pause, no injected messages after the
      initial brief.
- [ ] Every model→runtime action is a **native tool call** (structural: the
      runtime has no text-command parser — this criterion is satisfied by
      construction and asserted by the transcript schema).
- [ ] Within budgets: ≤ 24 iterations, ≤ 10 min wall-clock.

**C. Transcript completeness**
- [ ] The JSONL journal contains every provider request/response (with token
      usage), every tool call with validated arguments, every tool result
      (untruncated), every state transition, and the full run config (model
      tag + digest, seed, temperature, thinking mode, prompt version, tool
      schema versions, fixture hash).
- [ ] The final state of a run is **reconstructable from the journal alone**
      (proved by a replay test — §7).

**D. The repo's own gate**
- [ ] `pnpm typecheck` (strict, `noUncheckedIndexedAccess`) · `pnpm lint`
      (incl. the arch-guard: `core`/`tools` import no provider) · `pnpm test`
      (unit + integration, counts recorded) · `pnpm build` — all exit 0.

**E. Reproducibility artifact**
- [ ] `pnpm bench fix-failing-test` produces
      `benchmarks/results/<iso-timestamp>.json` — the scored report (per-run
      outcome, iterations, wall-clock, token usage, failure reasons) — plus the
      5 transcripts. Anyone with Ollama + qwen3:14b can reproduce the number.

## 4. Every interface that must exist

Shapes as specified in [ARCHITECTURE.md](ARCHITECTURE.md) §6–7; v0.1 implements
exactly these, no more:

| Interface | Home | v0.1 scope notes |
|---|---|---|
| `RuntimeMessage`, `ToolCall`, `AssistantMessage` | `core/messages.ts` | The normalized message model. `ToolCall.arguments` is always a parsed object. |
| `Clock`, `IdGen`, `Rng` | `core/inject.ts` | Injected everywhere; wall-clock and randomness banned in core paths (lint-guarded). |
| `AgentSession` | `core/session.ts` | `create(config)`, `runTurn(input): Promise<TurnResult>`, `abort()`. One session, one message log. |
| `TurnResult` | `core/loop.ts` | `{ outcome: 'completed' \| 'max_iterations' \| 'budget_exceeded' \| 'aborted' \| 'provider_failed'; finalText; iterations; usage }` |
| `RuntimeEvent` | `core/events.ts` | Discriminated union: `turn_started`, `infer_request`, `infer_response`, `tool_call`, `tool_result`, `policy_denied`, `turn_finished`, `session_error`. The transcript is this stream, serialized. |
| `Provider`, `ChatRequest`, `ChatResponse`, `ModelCapabilities` | `providers/types.ts` | Non-streaming only. `capabilities()` drives `num_ctx` and the thinking flag. |
| `Tool`, `ToolContext`, `ToolResult`, `ToolError` | `tools/types.ts` | Includes `safety` and `timeoutMs` fields from day one (values trivial in v0.1; the shape must not change later). `ToolContext.surface` implemented as the write allowlist. |
| `ToolRegistry` | `tools/registry.ts` | `register(tool)`, `jsonSchemas()`, `execute(call, ctx)` — executor owns validation, timeout, error-as-message. |
| `TranscriptWriter` / `TranscriptReader` | `host/transcript.ts` | Append-only JSONL, write-ahead; reader reconstructs session state (replay). |
| `BenchmarkSpec`, `RunResult`, `BenchmarkReport` | `bench/spec.ts` | Zod-validated; `benchmark.json` parses through `BenchmarkSpec`. |
| `RuntimeConfig` | `host/config.ts` | Ollama base URL, model overrides, scratch dir. Zod-validated; `host/` is the only layer reading `process.env`. |

## 5. Every runtime component

1. **The loop** (`core/loop.ts`) — the ASSEMBLE → INFER → EXECUTE state machine
   from ARCHITECTURE.md §5, with v0.1 simplifications: context assembly is
   *naive full history* (system prompt + brief + every message verbatim — the
   fixture is tiny; the ledger/compaction arrive in v0.4). Guards: max
   iterations, wall-clock budget, AbortSignal. Tool errors return to the model
   as tool-result messages; only infrastructure failures abort the turn.
2. **Tool executor** (`tools/registry.ts`) — lookup (unknown tool → error
   result), Zod validation (failure → error result carrying the validation
   message so the model self-corrects), execution under per-tool timeout,
   sequential in v0.1 (parallel execution is v0.2; qwen3 rarely batches calls).
3. **Ollama adapter** (`providers/ollama/`) — `POST /api/chat` with `tools`,
   `stream: false`; reads `message.tool_calls[].function.{name, arguments}`
   (arguments arrive as parsed objects; adapter mints call ids when absent).
   Sets `num_ctx` explicitly from the capability entry and **refuses to run**
   with an unconfigured window. Sets `think` per the capability entry. One
   `withRetry` at the boundary (backoff + jitter; retries connection errors and
   5xx; respects `Retry-After`).
4. **Model capability table** (`providers/ollama/models.ts`) — data entries for
   `qwen3:14b` (required) and `qwen3:8b` (comparison): `nativeTools: true`,
   `contextWindow`, recommended sampling, thinking support. Config-overridable.
5. **Transcript** (`host/transcript.ts`) — every `RuntimeEvent` serialized to
   `sessions/<id>/journal.jsonl` *before* the state transition applies
   (write-ahead). Reader rebuilds the message log for the replay test.
6. **Benchmark harness** (`bench/harness.ts`) — per execution: prepare the
   cached fixture template (frozen install, once) → for each seed: copy
   template to a fresh scratch workspace → hash protected files → create
   session (Architect prompt + task brief + workspace-rooted tools with the
   write surface) → `runTurn` → **independent verification** (`bench/verify.ts`:
   harness runs the test command itself under `timeout`, captures the real exit
   code; re-hashes protected files; scans the transcript for criteria B) →
   `RunResult`. Then score 5 results → `BenchmarkReport` → write to
   `benchmarks/results/`.
7. **CLI** (`host/cli.ts`) — `crucible bench fix-failing-test [--model …]
   [--runs …]` and `crucible chat` (a plain debug REPL over one session — the
   dev tool you'll actually use while building; not part of the exit criteria).

## 6. Every native tool required (five, exactly)

Small models do better with fewer, sharper tools. v0.1 ships exactly five; all
paths are workspace-rooted and resolved paths outside the workspace are denied.

| Tool | Signature (Zod-schema'd) | Notes |
|---|---|---|
| `read_file` | `{ path, offset?, limit? }` | Line-numbered output; `forModel` degrades head+tail if huge (trivial in the fixture, but the shape is permanent). |
| `list_dir` | `{ path }` | Recursive listing with sizes; enough for a 6-file fixture (no `glob` in v0.1). |
| `grep` | `{ pattern, path? }` | Literal + regex search, matches with line numbers. |
| `write_file` | `{ path, content }` | Full overwrite. **Enforces `ToolContext.surface`** — the fixture allows `src/**` only; a denied write returns a policy error result the model can read and react to. |
| `run_command` | `{ command, timeoutMs? }` | cwd pinned to the workspace; hard timeout (default 120 s, cap 300 s); returns `{ exitCode, stdout/stderr tail }`. Exit 124 rendered explicitly as *"command timed out — this is a hang, not a pass."* |

Explicitly absent until later: `edit_file` (v0.2), `glob` (v0.2), git tools
(v0.2), `ask_director` (v0.3) — the benchmark requires zero human interaction,
so its absence is a feature.

## 7. The benchmark fixture repository

**Design goals:** the bug must be *semantic* (invisible to the typechecker, so
the loop is exercised, not `tsc`), *localized* (one function, one file),
*unambiguous* (exactly one correct fix, judged by the tests), and the task
must *require* reading the test to understand intent.

- **Module:** `src/interval.ts` — `overlaps(a: Interval, b: Interval): boolean`
  for closed intervals. **Planted bug:** strict `<` where `<=` is required, so
  intervals that touch at a boundary (e.g. `[1,5]` and `[5,9]`) incorrectly
  report no overlap. Classic boundary-condition bug: realistic, typecheck-clean,
  one-line semantic fix.
- **Tests:** `test/interval.test.ts` — 3 cases: disjoint → `false` (passes),
  clearly overlapping → `true` (passes), **touching at a boundary → `true`
  (fails against the bug)**. Test names state intent in plain language — the
  agent's signal for what *correct* means.
- **Scripts:** `"test": "vitest run"` — never watch mode (a watch-mode default
  would hang every run; this is the §4-prevention lesson applied to our own
  benchmark). `vitest.config.ts` sets `testTimeout` so a pathological edit
  fails fast instead of wedging the runner.
- **Protected files** (hash-verified + write-denied): `test/**`,
  `vitest.config.ts`, `package.json`, `tsconfig.json`, `pnpm-lock.yaml`.
- `benchmark.json` (the `BenchmarkSpec`): model pin, 5 seeds, budgets
  (24 iterations / 10 min), `testCommand: "pnpm test"`, `writableSurface:
  ["src/**"]`, protected-file hashes, prompt version.

The fixture is committed as plain source (no `node_modules`); the harness owns
dependency staging (§1, hermeticity).

## 8. Testing strategy

Three rings, strictly separated:

**Ring 1 — unit (CI, deterministic, no model, no network).**
FakeProvider + FakeClock throughout.
- Loop: happy path (text → done), single/multi tool-call rounds, unknown tool →
  error-result → model recovers, invalid args → validation-message → model
  retries with fixed args, max-iterations, wall-clock budget, abort mid-turn,
  provider failure after retries.
- Tool executor: Zod rejection shapes, timeout → exit-124-style error result,
  workspace escape attempts (`../`, absolute paths, symlinks) denied, write
  surface denial.
- Ollama translation: golden wire-format fixtures both directions (incl. a
  captured real qwen3 tool-call response), id-minting, `num_ctx` refusal.
- Transcript: write-ahead ordering, replay reconstructs the exact message log.
- `withRetry`: backoff schedule under FakeClock, Retry-After honored, gives up
  correctly.

**Ring 2 — integration (CI, deterministic, no model).**
The **full benchmark harness** run with a FakeProvider *scripted to fix the
fixture* (and variants: one that edits a protected file → run must be scored
failed; one that never runs the tests first → scored failed; one that exceeds
iterations). This proves the harness, staging, verification, hashing, and
scoring end-to-end without a GPU — and it means **CI validates everything
except the model itself**, which is exactly the separation the benchmark
exists to create ("runtime broken" vs "model confused").

**Ring 3 — live benchmark (local, not CI).**
`pnpm bench fix-failing-test` against real Ollama + qwen3:14b. Produces the
scored report + transcripts. This is the v0.1 exit gate, run by a human on
pinned hardware; results (report JSON) are committed for the record. Golden
transcripts from interesting live runs get sanitized into Ring-1 fixtures.

**Standing repo gate** (constraint #8): `typecheck · lint(+arch-guard) ·
test(counts recorded) · build` — green on every commit from the first one.

## 9. Revised roadmap — v0.1 → v1.0

v0.1 is re-scoped to the benchmark kernel (this spec). The old 0.1/0.2 split
("read-only first, writes later") is dissolved — the benchmark needs
`write_file` + `run_command` on day one. Downstream phases are unchanged in
substance, and **every phase re-runs the v0.1 benchmark as a regression gate**:
the 5-run pass rate must never drop.

| Version | Slice | Lands | Exit demo |
|---|---|---|---|
| **0.1** | **Benchmark kernel** | This spec: loop, Ollama adapter, 5 tools, transcript, harness, fixture | **≥ 4/5 on qwen3:14b, zero intervention** |
| 0.2 | Tools + policy | Full safety classes, `edit_file`, `glob`, targeted-git tool, generalized surface enforcement, parallel tool execution | Policy denial + self-correction demo; benchmark pass rate holds |
| 0.3 | Roles + prompts | Prompt packs (interpolation engine), `AgentRole` manifests, `ask_director` + paused-for-approval, config system | Architect grills with structured questions before executing |
| 0.4 | Context manager | Token ledger, layered assembly, tool-result degradation, compaction, durable memory, resume-cold; optional `chatStream` | Session 3× the window completes; kill mid-turn, resume, finish |
| 0.5 | Second provider | Anthropic + OpenAI-compatible adapters; **the benchmark becomes the parity suite** — same spec, any provider; package split (per Director decision) | Benchmark passes on Claude by changing one config line |
| 0.6 | Builders | `dispatch_builder` → child-process sessions, dispatch briefs, per-role models, dispatch-time disjointness checks | Two parallel builders, disjoint surfaces, targeted commits |
| 0.7 | Supervision | Heartbeat supervisor, mtime+commit liveness (§D), stall/death detection, salvage → wip checkpoint → continuation relaunch | Kill a builder mid-task; salvaged, relaunched, slice finishes |
| 0.8 | Verification | Gate runner (real exit codes, per-command timeouts, test-count drift), Validator role, verify-on-completion-claim | A builder that lies "all green" is caught; slice does not advance |
| 0.9 | Persistence + AFK | Review queue, status/memory conventions, notifications, boundary pause/resume across restarts, per-slice cost accounting | Multi-slice run completes AFK with full audit trail |
| 1.0 | The pipeline, whole | Grill→plan→dispatch→supervise→verify→recover→persist→advance continuous; hardening, golden transcripts, frozen API, semver | A real multi-slice feature on a real repo, Director checks in twice |

**Immediately after v0.1 succeeds** (before 0.2 proper): run the optional
comparison models (`qwen3:8b`, coding-tuned models) through the same harness
and commit the reports — the first data for the capability table and for the
eventual "cheap Builders / strong Architect" routing decision.

**If v0.1 fails** (< 4/5 after honest prompt/config iteration): that is the
benchmark doing its job. The recorded escalation path: larger pin (30b-a3b) →
coding-tuned models → re-evaluate the local-first premise with data in hand.
The runtime code survives any of these outcomes unchanged — only the capability
table and the pin move.
